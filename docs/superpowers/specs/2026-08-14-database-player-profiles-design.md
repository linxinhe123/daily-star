# 数据库球员标准档案设计

## 目标

保持现有每日猜球玩法不变，让数据库中的 200 名球员都拥有可识别、可阅读、无空白入口的正式档案。莫德里奇等人工精选资料继续作为最高优先级增强内容。

## 数据分层

- `StatBunker`：赛季、出场、首发、进球、助攻和俱乐部汇总。
- `TheSportsDB`：照片、国籍、生日、身高、惯用脚、位置、号码和当前俱乐部。
- 本地中文表：球员常用中文名、国家和位置翻译。
- 人工精选资料：完整简介、关键节点、荣誉和身价历史；同字段覆盖自动档案。

所有外部数据在同步阶段写入本地 JSON 和 SQLite。网页运行时不请求第三方接口。

## 页面行为

- 档案列表以中文名为主标题，英文名为副标题；有照片则显示照片，否则使用当前俱乐部队徽和姓名组成正式封面。
- 详情首屏显示中文名、英文名、国籍、位置、当前俱乐部、号码和照片，不出现“档案待补充”。
- 概览显示事实型简介、生日、身高、惯用脚、职业年代和当前俱乐部。
- 数据页继续展示真实赛季数据；生涯页由赛季数据自动生成俱乐部履历。
- 仅在存在可靠数据时显示身价和荣誉模块；不显示空标签或空白卡片。
- 提问页使用已生成的身份、俱乐部和比赛数据回答基础问题。

## 降级规则

- 没有球员照片：使用当前俱乐部队徽封面。
- 没有中文名：保留英文名，但同步报告将其列为未完成，不静默通过。
- 没有生日、身高或惯用脚：隐藏对应字段。
- 没有荣誉或身价数据：隐藏对应模块和标签，不编造内容。

## 验收

- 200 名数据库球员均有中文主名。
- Isak 能显示中文名、真实照片、瑞典、位置、生日、身高、惯用脚、当前俱乐部和俱乐部履历。
- 莫德里奇现有深度资料不回退。
- 桌面端和 393px 移动端无横向滚动、空标签、空链接或控制台错误。
