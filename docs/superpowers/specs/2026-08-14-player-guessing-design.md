# 「猜球星」无限猜与档案完整性设计

## 目标

将当前的「每日一星」改造为可连续游玩的「猜球星」，使全部资料完整的档案球员都能进入随机题库。同时修复档案、收藏、分享、搜索和问答中已确认的数据与状态问题，并用可重复执行的采集流程补齐身价曲线和退役球员生涯轨迹。

## 产品语义

- 产品名称、导航和页面文案统一为「猜球星」，不再宣称每日唯一题目。
- 移除「今日第几天」和固定「连续 7 天」。侧边栏改为基于本地真实记录的已完成局数和猜对数。
- 每局结束后的主要动作为「再猜一位」，总是从可玩池中抽取新球员，不沿用从档案页打开的球员。
- 档案详情与游戏状态分离：查看任意档案不会改变当前题目、尝试次数或胜负统计。

## 玩法与线索

### 可玩球员池

球员只有同时满足以下条件才进入随机池：

- 有可展示的中文名和英文名。
- 有已核验的国籍、位置和至少一段俱乐部经历。
- 能生成至少 5 条不直接泄露姓名的可靠线索。

资料不足的球员仍可出现在档案，但在补齐前不进入猜题池。页面不向用户显示内部的「待补全」标记。

### 线索生成

人工编写的精选球员线索保留。其他球员由结构化档案生成 7 至 9 条候选线索，可用信息包括：

- 国籍或所属足球地区。
- 主要位置和技术特点。
- 职业生涯起止年代。
- 已效力俱乐部数量或跨越的联赛。
- 不直接暴露答案的俱乐部轨迹。
- 已核验的代表荣誉、出场、进球或助攻数据。
- 身高、惯用脚或球衣号码，仅在不会导致线索过强时使用。

开始一局时，从候选线索中随机抽取 5 条并随机排序。不固定国籍、位置、俱乐部或数据的出现顺序。同一局的线索顺序在刷新后保持一致，新局重新洗牌。

### 随机规则

- 新局不与上一局球员重复。
- 使用本地随机局 ID 持久化球员、线索顺序、尝试次数和局状态。
- 刷新页面恢复当前局，不重抽答案。
- 连续局数、完成局数和猜对数使用 `localStorage` 持久化，不伪装为账号云同步。

## 页面状态与 URL

不引入大型路由依赖，使用 History API 管理页面状态：

- `/` 显示当前猜题。
- `/?view=archive` 显示档案列表。
- `/?player=<slug>` 显示指定球员档案。
- `/?view=saved` 显示收藏。
- `/?view=about` 显示关于。

`openPlayer` 只更新档案视图和 URL，不覆盖当前猜题。初次加载和 `popstate` 都从 URL 恢复视图。分享使用球员专属 URL，非 HTTPS 或不支持系统分享时复制该 URL。

## 收藏

- 详情页主操作区增加收藏按钮，图标和文案反映当前状态。
- 收藏保存球员 slug 数组，从 `players` 中派生真实卡片，不复制球员数据。
- 收藏页复用档案卡片样式，支持打开详情。无收藏时才显示当前的空状态。
- 本地存储损坏时回退为空收藏，不阻断页面加载。

## 搜索和图片降级

搜索统一对中文名、英文名、别名、国籍、位置和效力俱乐部做小写化匹配。搜索结果为空时显示「未找到匹配球员」和清空搜索操作。

精选球员优先使用已同步的本地图片，不再依赖失效的 Wikimedia 热链。图片不存在或加载失败时，卡片使用中性留白、球员中文姓名和国旗作为降级视觉，不再显示空灰块、失效图标或装饰性球衣号码。

## 退役状态与档案完整性

`_Retired Soccer` 和 `_Free Agent Soccer` 是供应商占位值，不能作为俱乐部进入前端数据。

- `active === false` 的球员显示「已退役」，隐藏「当前俱乐部」指标。
- 占位值在数据生成层转换为空值，前端仍做二次防御，避免旧快照泄漏。
- 「效力俱乐部」以生涯轨迹数据为准，不再用 StatBunker 已覆盖赛事的俱乐部列表冒充完整生涯。
- 球员详情中分开「完整效力轨迹」与「已覆盖赛事统计」，允许早期俱乐部只有年份而没有可比的出场数。

## 数据管线

### 身价曲线

使用 Transfermarkt 开放数据集的 `player_valuations.csv.gz` 和已有的 Transfermarkt ID：

1. 将 200 人名单的 Transfermarkt ID 作为采集边界。
2. 按球员保留估值日期、欧元价值和当时俱乐部 ID。
3. 写入 SQLite 独立表，并导出前端 JSON 快照。
4. 图表使用真实日期点，不伪造年度补点。节点过密时只在显示层抽样，保留原始数据。

对于 Transfermarkt 尚未建立历史估值的早期球员，不使用通胀换算或当代估算补数。页面显示「该年代无可核验的历史估值记录」。

### 完整生涯轨迹

使用 Transfermarkt ID 获取球员效力历史，对请求做限速、失败继续和本地缓存。每段保存俱乐部、开始时间、结束时间和来源。数据按时间排序后合并连续的同俱乐部阶段，回归老东家的非连续阶段保持分开。

优先补全所有退役球员，再对现役球员执行同一流程。生涯轨迹与 StatBunker 赛事统计用球员 slug 关联，但不因后者缺失而删除前者。

## 球星问答边界

问答根据当前球员实际模块组装回答：

- 退役球员回答「已退役」，不输出占位俱乐部。
- 只有 `marketValues.length > 0` 才宣称已整理身价趋势。
- 只有已核验的荣誉、数据和俱乐部才进入回答。
- 缺少对应模块时直接说明整理边界，不用泛化营销文案替代事实。

## 模块边界

- `game-session.ts`：可玩池、随机抽取、线索洗牌、局状态和统计持久化。
- `player-clues.ts`：从结构化球员数据生成候选线索，不读写 UI 状态。
- `navigation.ts`：URL 解析、History API 更新和 `popstate` 恢复。
- `favorites.ts`：收藏 slug 的读写和损坏数据回退。
- `player-data.ts`：前端的球员详情合并，负责隐藏占位值并分开轨迹、统计和身价。
- 同步脚本：负责身价和完整生涯的采集、SQLite upsert、JSON 导出和覆盖率报告。
- `App.vue`：组合上述模块和页面显示，不再直接承担随机、持久化和 URL 解析细节。

## 错误处理

- 数据同步对单个球员失败时记录 slug、来源和原因，继续处理其他球员，最后以非零状态输出覆盖率报告。
- 网络原始响应写入缓存，重跑时默认复用，支持显式刷新。
- 球员 slug 或 URL 无效时返回档案列表并显示轻量提示，不进入空详情。
- 随机池为空时显示资料整理状态，禁用提交按钮，不让用户进入无线索游戏。

## 验证

实现完成后执行以下验证：

- 生产构建和 TypeScript 检查。
- 随机抽取不重复上一位，每局恰好 5 条线索，线索顺序可变且刷新后稳定。
- 从普通档案进入详情后再开一局，题目不受档案球员污染。
- 收藏、取消收藏、刷新恢复和收藏页打开详情。
- 球员专属 URL 直达、刷新恢复、前进后退和分享 URL。
- 按「门将」、国籍、俱乐部和不存在的关键词搜索。
- 退役球员不出现 `_Retired Soccer`、「现效力」或伪造的当前身价。
- 布冯包含帕尔马首次效力、尤文图斯、巴黎圣日耳曼、尤文图斯回归和帕尔马回归。
- 所有退役球员都有轨迹覆盖率报告，不将早期数据缺失当作零数据。
- 现代球员身价节点可视化，早期球员显示真实的无记录边界。
- 桌面和 390px 左右手机视口无水平滚动，收藏按钮、无结果状态和图片降级均可见。

## 非目标

- 不引入用户账号、云同步或排行榜。
- 不把国家队数据混入俱乐部出场、进球和助攻统计。
- 不伪造无可核验来源的历史身价、荣誉或早期赛事数据。
- 不在浏览器运行时请求 Transfermarkt 或 StatBunker。
